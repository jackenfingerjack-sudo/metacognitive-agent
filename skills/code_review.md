# Code Review

**When to use:** Reviewing code or a pull request for quality and correctness.

## Steps
1. Understand the intent and context of the change.
2. Check correctness: logic, edge cases, error handling.
3. Assess readability: naming, structure, comments.
4. Look for security, performance, and concurrency issues.
5. Verify tests exist and cover the change.
6. Give prioritized feedback (blocking vs. nit) with concrete fixes.
